# The Primitive Shift

Most of what we call "software" is structured context plus decision-making.

---

## What We Built

We started with 20,000 words of architecture — Policy DSLs, Coverage Loops, Decision Traces, Context Graphs, Network Health Scores. Layers of encoded logic designed to capture reasoning, detect patterns, coordinate decisions, learn from outcomes.

Then the realization: **an LLM already does all of that natively**. We were engineering in code what intelligence does with context. The entire architecture was a description of cognition, written by people who didn't yet have access to cognition as infrastructure.

## The Primitive Changed

When the primitive changes, you can't subtract your way to the new thing. You can't edit a 20,000-word architecture document into a markdown file and a conversation. You have to start from zero because the old architecture was the *right answer to the wrong primitive*. It wasn't bad engineering. It was engineering for a world where you had to build the reasoning yourself.

Now you don't.

## The Collapse

Every domain with a complex software system encoding human judgment has its own 20,000-word architecture with its own Policy DSLs and Decision Trace equivalents. Teams are building them right now. They're correct — *for the old primitive*.

When intelligence becomes infrastructure, the architecture collapses into a context file, a system prompt, and tool access. Not because you're cutting corners — because the load-bearing work moved from code to cognition.

- Legal case management → `case.md` + an agent
- Project management → `project.md` + an agent
- Clinical trial coordination → `trial.md` + an agent
- Real estate transactions → `deal.md` + an agent
- Care coordination → `family.md` + an agent

The pattern is the same. A well-structured text file that an intelligence reads at the start of every interaction. The file shapes the behavior. The conversation is ephemeral. The file persists. That's the whole thing.

## The Proof Was Already There

`CLAUDE.md` already proved this. Every time a developer opens a session, the file shapes the behavior. The conversation is ephemeral. The file persists. Software architecture became prompt architecture, and the people using it every day were the last to name it.

`family.md` is `CLAUDE.md` pointed at care instead of code.

## The Uncomfortable Truth

The people building the 20,000-word architectures aren't wrong. They just haven't noticed the primitive changed yet. And the gap between noticing and not noticing is about to become the widest competitive moat in software.

Software architecture is becoming context architecture. The teams that see this will ship in weeks what others plan for quarters. Not because they're faster — because the load-bearing work is already done. It's called intelligence. You just have to give it the right file.
